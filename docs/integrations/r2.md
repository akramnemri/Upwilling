# Cloudflare R2 — verified requirements

Checked 2026-11-01 against Cloudflare's docs. Used by database backups (ADR-026); media and private files come later
(ADR-008). **Nothing here has run against real R2 yet**: there is no account. The S3 path of the backups is tested
against rclone's own S3 server (`infra/server/test/smoke-backup.sh`).

| Topic | Verified |
|---|---|
| Account | Needs an R2 subscription, added through a checkout flow. The docs do not say whether it asks for a card, and third-party guides disagree. Human step. |
| Free tier (monthly, Standard storage only) | 10 GB-month, 1 million Class A and 10 million Class B operations, no egress charges. |
| S3 endpoint | `https://<accountid>.r2.cloudflarestorage.com` |
| rclone | v1.59 or later (we pin 1.75.2): `type = s3`, `provider = Cloudflare`, `acl = private`. |
| Object-level token | Needs `no_check_bucket = true`, or rclone may get errors. |

## Backups

In `<server folder>/backup/.env` (rclone reads remotes from `RCLONE_CONFIG_<REMOTE>_<OPTION>`, ADR-026):

```text
BACKUP_DESTINATION=r2:<bucket>
RCLONE_CONFIG_R2_TYPE=s3
RCLONE_CONFIG_R2_PROVIDER=Cloudflare
RCLONE_CONFIG_R2_ENDPOINT=https://<accountid>.r2.cloudflarestorage.com
RCLONE_CONFIG_R2_ACL=private
RCLONE_CONFIG_R2_NO_CHECK_BUCKET=true
RCLONE_CONFIG_R2_ACCESS_KEY_ID=
RCLONE_CONFIG_R2_SECRET_ACCESS_KEY=
```

A token limited to the backup bucket is enough. The secret key goes only in that file, written by a human.
Steps: `docs/runbooks/backup-restore.md` §7.
